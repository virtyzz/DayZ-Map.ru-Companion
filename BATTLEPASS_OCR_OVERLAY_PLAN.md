- [x] Сканирование ежедневной страницы и обеих недельных страниц с отдельным обновлением каждой страницы.

- [x] Горячие клавиши и пункты трея для показа, сканирования и настройки Battle Pass.
- [x] OCR описания, XP-награды и текстового статуса; прогресс дополнительно проверяется по `current/target`.

- [x] Горячая клавиша переключения режима отображения.
- [x] Сборка проекта и существующий набор автоматических тестов, включая нормализацию OCR-настроек Battle Pass.
- [ ] Ручная проверка на реальном интерфейсе DayZ при разных разрешениях и UI-масштабах: требует запущенной игры и набор скриншотов пользователя.

## Цель

Добавить в DayZ Map Companion локальный трекер Battle Pass, который по запросу считывает видимый интерфейс игры через скриншот и Tesseract OCR, сохраняет последнее распознанное состояние и показывает задания в настраиваемом экранном оверлее.

## Границы решения

- Источник данных — только изображение экрана или окна DayZ.
- Не используются чтение памяти, DLL-инъекции, DirectX-хуки, перехват сетевого трафика и изменение модов игры.
- Обновление выполняется пользователем по горячей клавише, когда открыт соответствующий экран Battle Pass.
- Ежедневные задания считываются с одной страницы; еженедельные — с двух страниц, которые пользователь последовательно открывает и сканирует.

## Этап 1. Модель данных и хранение

1. Добавить модель `BattlePassSnapshot`:
   - дата и время последнего сканирования;
   - уровень, XP и баланс (если успешно распознаны);
   - списки ежедневных и еженедельных заданий;
   - признак, какие недельные страницы уже считаны.
2. Добавить модель `BattlePassTask`:
   - период: daily или weekly;
   - номер страницы и позиция на странице;
   - название и описание;
   - текущий и целевой прогресс;
   - XP-награда;
   - статус выполнения;
   - время последнего обновления.
3. Хранить снимок локально в JSON рядом с настройками приложения.
4. Стабильно сопоставлять повторно считанные задания по нормализованному названию; при неудаче использовать страницу и позицию.

## Этап 2. Скриншот и сценарий синхронизации

1. Добавить горячую клавишу «Считать Battle Pass».
2. При её нажатии сделать снимок выбранного монитора либо окна DayZ.
3. В настройках дать пользователю выбрать тип текущего снимка:
   - ежедневные задания;
   - еженедельные, страница 1;
   - еженедельные, страница 2.
4. После обработки показать краткий результат: сколько заданий найдено и какие поля не удалось распознать.
5. Не запускать постоянный OCR в первой версии.

## Этап 3. Распознавание интерфейса

1. Использовать Tesseract с языками `rus+eng`, которые уже поставляются с приложением.
2. Привязать зоны OCR к относительным координатам интерфейса Battle Pass, а не к одному разрешению:
   - область названия задания;
   - область описания;
   - область XP;
   - область статуса;
   - область счётчика `текущий/цель`.
3. Перед распознаванием применять подготовку изображения: масштабирование, повышение контраста и бинаризацию.
4. Извлекать прогресс регулярным выражением `^(\\d+)\\s*/\\s*(\\d+)$`; не рассчитывать его по длине оранжевой полосы.
5. Определять статус по тексту «ВЫПОЛНЕНО» / «НЕ ЗАВЕРШЕНО» и по равенству текущего прогресса цели.
6. Сохранять исходный скриншот последнего сканирования только при включённой отладке, чтобы не копить лишние изображения.

## Этап 4. Проверка и ручная коррекция

1. Добавить в настройки страницу «Battle Pass» с таблицей распознанных заданий.
2. Показывать значения, в которых OCR не уверен или не нашёл счётчик.
3. Разрешить вручную исправить название, прогресс и статус; изменения сохранять локально.
4. Добавить кнопку очистки данных Battle Pass.

## Этап 5. Оверлей заданий

1. Создать отдельное окно оверлея заданий, не смешивая его с существующим оверлеем прицела.
2. В обычном режиме окно:
   - прозрачное, поверх остальных окон и click-through;
   - отображается на выбранном мониторе;
   - использует последнее локально сохранённое состояние.
3. В режиме редактирования отключать click-through и показывать рамку, чтобы окно можно было переместить и изменить его размер.
4. Сохранять позицию, размер, масштаб шрифта, прозрачность и выбранный монитор.
5. Добавить варианты содержимого:
   - все активные задания;
   - только незавершённые;
   - только закреплённые пользователем;
   - ежедневные, недельные или оба типа.
6. Для каждой строки показывать название, `текущий/цель`, короткую полосу прогресса и статус выполнения.

## Этап 6. Горячие клавиши и UX

1. Добавить настраиваемые горячие клавиши:
   - показать/скрыть оверлей заданий;
   - считать текущую страницу Battle Pass;
   - включить/выключить режим редактирования;
   - переключить профиль отображения.
2. В интерфейсе дать короткую инструкцию синхронизации:
   - открыть вкладку ежедневных и считать её;
   - открыть недельные, считать первую страницу;
   - перелистнуть на вторую и считать её.
3. Показывать время последней успешной синхронизации, чтобы пользователь понимал актуальность оверлея.

## Этап 7. Тестирование

1. Собрать набор скриншотов с разными разрешениями, масштабом UI и состояниями заданий.
2. Проверить распознавание пустого, частичного и завершённого прогресса.
3. Проверить слияние двух недельных страниц и повторное обновление одной из них.
4. Проверить позиционирование оверлея на нескольких мониторах и после смены разрешения.
5. Проверить работу в оконном и borderless-режиме DayZ. Эксклюзивный fullscreen может не отображать стандартный оконный оверлей Windows.

## Последовательность первого релиза

1. Локальные модели и JSON-хранилище.
2. Снимок экрана по горячей клавише.
3. OCR счётчиков прогресса и названий видимых заданий.
4. Экран проверки распознанных данных.
5. Компактный оверлей с ручным позиционированием.
6. Поддержка второй страницы еженедельных заданий.

## Критерий готовности MVP

Пользователь может открыть Battle Pass, последовательно считать ежедневную страницу и обе недельные страницы, а затем во время игры видеть в выбранной части экрана сохранённый список незавершённых заданий с корректным прогрессом.
